Security at Scale: Authentication & Authorization

A comprehensive system design guide covering patterns from basic to advanced implementations in modern tech stacks.

1. Core Concepts

Authentication (AuthN)

Who are you? Verifying user identity through credentials, tokens, or biometrics.

  • Password-based login
  • Multi-factor authentication (MFA)
  • OAuth2 / OIDC providers
  • Biometric verification

Authorization (AuthZ)

What can you do? Determining access rights after identity is confirmed.

  • Role-Based Access Control (RBAC)
  • Attribute-Based Access Control (ABAC)
  • Policy engines (OPA, Cedar)
  • Resource-level permissions

2. Architecture Patterns

Pattern A: Monolithic Auth (Basic)

Basic
┌─────────────┐ ┌──────────────┐ ┌─────────────┐ │ Client │────▶│ App Server │────▶│ Database │ │ (Browser) │◀────│ (Express.js) │◀────│ (MongoDB) │ └─────────────┘ └──────────────┘ └─────────────┘ │ ┌────▼─────┐ │ Session │ │ Store │ └──────────┘

All auth logic lives in the application server. Simple to implement but becomes a bottleneck at scale.

Pattern B: API Gateway + Auth Service (Intermediate)

Intermediate
┌──────────┐ ┌─────────────┐ ┌──────────────┐ │ Client │───▶│ API Gateway │───▶│ Auth Service │ └──────────┘ └─────────────┘ └──────────────┘ │ │ ┌────▼─────┐ ┌────▼─────┐ │ Services │ │ User DB │ │ (Micro) │ └──────────┘ └──────────┘

Centralized auth at the gateway layer. JWTs propagate identity to downstream services.

Pattern C: Zero-Trust Mesh (Advanced)

Advanced
┌──────────┐ ┌──────────┐ ┌──────────┐ │ Service A│ │ Service B│ │ Service C│ └────┬─────┘ └────┬─────┘ └────┬─────┘ │ │ │ └──────────────┼──────────────┘ │ ┌────────▼────────┐ │ Service Mesh │ │ (mTLS + OPA) │ └─────────────────┘

Every service-to-service call is authenticated and authorized. Uses mutual TLS and policy enforcement points.

3. Implementation Examples

JWT Authentication Flow

// Backend: Express.js + JWT
const jwt = require('jsonwebtoken');
const bcrypt = require('bcrypt');

// Login endpoint
app.post('/api/login', async (req, res) => {
  const { email, password } = req.body;
  const user = await db.users.findOne({ email });

  if (!user || !await bcrypt.compare(password, user.passwordHash)) {
    return res.status(401).json({ error: 'Invalid credentials' });
  }

  const token = jwt.sign(
    { sub: user.id, role: user.role },
    process.env.JWT_SECRET,
    { expiresIn: '1h', issuer: 'auth-service' }
  );

  res.json({ accessToken: token, refreshToken: user.refreshToken });
});

// Auth middleware
function authenticate(req, res, next) {
  const authHeader = req.headers.authorization;
  if (!authHeader?.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Missing token' });
  }

  try {
    const payload = jwt.verify(authHeader.slice(7), process.env.JWT_SECRET);
    req.user = payload;
    next();
  } catch (err) {
    res.status(401).json({ error: 'Invalid token' });
  }
}

RBAC Authorization Middleware

// Role-based access control
const ROLES = {
  ADMIN: 'admin',
  EDITOR: 'editor',
  VIEWER: 'viewer'
};

function authorize(...requiredRoles) {
  return (req, res, next) => {
    if (!req.user || !requiredRoles.includes(req.user.role)) {
      return res.status(403).json({ error: 'Insufficient permissions' });
    }
    next();
  };
}

// Usage
app.get('/api/admin/users',
  authenticate,
  authorize(ROLES.ADMIN),
  async (req, res) => {
    const users = await db.users.find();
    res.json(users);
  }
);

OAuth2 with PKCE (Public Clients)

// Frontend: React OAuth2 flow with PKCE
import { useEffect, useState } from 'react';

function generateCodeVerifier() {
  const array = new Uint8Array(32);
  crypto.getRandomValues(array);
  return btoa(String.fromCharCode(...array)).replace(/[^a-zA-Z0-9]/g, '');
}

async function generateCodeChallenge(verifier) {
  const encoder = new TextEncoder();
  const data = encoder.encode(verifier);
  const digest = await crypto.subtle.digest('SHA-256', data);
  return btoa(String.fromCharCode(...new Uint8Array(digest)))
    .replace(/\+/g, '-').replace(/\//g, '_').replace(/=/g, '');
}

export function useOAuth2() {
  const [verifier, setVerifier] = useState(null);

  const initiateLogin = async () => {
    const codeVerifier = generateCodeVerifier();
    const codeChallenge = await generateCodeChallenge(codeVerifier);
    setVerifier(codeVerifier);

    const params = new URLSearchParams({
      client_id: 'my-app',
      redirect_uri: window.location.origin + '/callback',
      response_type: 'code',
      code_challenge: codeChallenge,
      code_challenge_method: 'S256',
      scope: 'openid profile email'
    });

    window.location.href = `https://auth-provider.com/authorize?${params}`;
  };

  return { initiateLogin, verifier };
}

4. Security Best Practices

Token Management

1
Short-lived access tokens: 5-15 minutes for APIs, 1 hour for user sessions
2
Refresh token rotation: Issue new refresh token on each use, revoke old one
3
Secure storage: httpOnly cookies for web, encrypted storage for mobile
4
Token binding: Bind tokens to device fingerprint or IP range

Rate Limiting & Brute Force Protection

const rateLimit = require('express-rate-limit');
const RedisStore = require('rate-limit-redis');

// Login rate limiter
const loginLimiter = rateLimit({
  store: new RedisStore({
    client: redisClient,
    prefix: 'rl:login:'
  }),
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 5, // 5 attempts per window
  message: { error: 'Too many login attempts. Try again later.' },
  standardHeaders: true
});

app.post('/api/login', loginLimiter, handleLogin);

// Account lockout after failed attempts
async function checkAccountLockout(userId) {
  const key = `lockout:${userId}`;
  const attempts = await redis.incr(key);

  if (attempts === 1) {
    await redis.expire(key, 900); // Reset after 15 minutes
  }

  if (attempts > 5) {
    throw new Error('Account locked due to too many failed attempts');
  }
}

Policy Engine with Open Policy Agent (OPA)

# OPA Policy (Rego language)
package authz

import input

default allow = false

# Admin can access everything
allow {
  input.user.role == "admin"
}

# Editor can read and write resources in their department
allow {
  input.user.role == "editor"
  input.action in ["read", "write"]
  input.resource.department == input.user.department
}

# Viewer can only read public resources
allow {
  input.user.role == "viewer"
  input.action == "read"
  input.resource.visibility == "public"
}

// Node.js integration with OPA
async function checkPolicy(user, action, resource) {
  const response = await fetch('http://opa-server:8181/v1/data/authz/allow', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      input: {
        user: { id: user.id, role: user.role, department: user.department },
        action,
        resource: { id: resource.id, department: resource.department, visibility: resource.visibility }
      }
    })
  });

  const result = await response.json();
  return result.result;
}

// Usage in route
app.get('/api/resources/:id', authenticate, async (req, res) => {
  const resource = await db.resources.findById(req.params.id);

  const allowed = await checkPolicy(req.user, 'read', resource);
  if (!allowed) {
    return res.status(403).json({ error: 'Access denied' });
  }

  res.json(resource);
});

Zero-Trust Service-to-Service Auth

// Mutual TLS configuration
const https = require('https');
const fs = require('fs');

const agent = new https.Agent({
  ca: fs.readFileSync('/certs/ca.crt'),
  cert: fs.readFileSync('/certs/service-a.crt'),
  key: fs.readFileSync('/certs/service-a.key'),
  rejectUnauthorized: true
});

// Service call with mTLS
async function callServiceB(data) {
  const response = await fetch('https://service-b.internal/api/data', {
    method: 'POST',
    agent,
    headers: {
      'Content-Type': 'application/json',
      'X-Request-ID': crypto.randomUUID()
    },
    body: JSON.stringify(data)
  });

  return response.json();
}

6. Threat Model & Mitigations

Threat Mitigation Severity
Token theft via XSS httpOnly cookies, CSP headers, short TTL High
Brute force attacks Rate limiting, account lockout, MFA High
Privilege escalation Server-side validation, RBAC/ABAC, audit logs High
Session fixation Regenerate session ID on login, bind to device Medium
CSRF attacks SameSite cookies, CSRF tokens, double-submit Medium

7. Scaling Checklist

  • ✅ Implement centralized auth service or API gateway
  • ✅ Use JWTs with short expiration and refresh token rotation
  • ✅ Store sessions in distributed cache (Redis cluster)
  • ✅ Implement rate limiting per user/IP/endpoint
  • ✅ Enable comprehensive audit logging
  • ✅ Use policy engine (OPA/Cedar) for complex authorization
  • ✅ Implement mTLS for service-to-service communication
  • ✅ Regular security audits and penetration testing
  • ✅ Automated dependency scanning and patching
  • ✅ Incident response plan with runbooks
